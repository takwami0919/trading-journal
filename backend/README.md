# Trading Journal — Backend

FastAPI + PostgreSQL backend for the automated trading journal.

## Stack

- **FastAPI** — API layer
- **SQLAlchemy 2.0** — ORM / models (`app/models/`)
- **Alembic** — migrations (`alembic/`)
- **PostgreSQL** — database

## Setup

1. Create and activate a virtualenv, then install dependencies:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. Copy `.env.example` to `.env` and fill in real values:

   ```bash
   cp .env.example .env
   ```

   Generate the two secret values with:

   ```bash
   python3 -c "import secrets; print(secrets.token_hex(32))"                       # JWT_SECRET_KEY
   python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"  # CREDENTIAL_ENCRYPTION_KEY
   ```

3. Make sure Postgres is running and the database in `DATABASE_URL` exists:

   ```bash
   createdb trading_journal
   ```

4. Run migrations:

   ```bash
   alembic upgrade head
   ```

5. Start the dev server:

   ```bash
   uvicorn app.main:app --reload
   ```

6. Confirm it's alive:

   ```bash
   curl http://localhost:8000/health
   # {"status":"ok","environment":"development"}
   ```

## Project layout

```
app/
  core/        # config, database session, (soon) security/crypto helpers
  models/      # SQLAlchemy models — one file per logical group of tables
  api/         # FastAPI routers (empty for now — built in the next step)
  services/    # business logic: trade matching, sync, analytics
  adapters/    # BrokerAdapter interface + AlpacaAdapter implementation
alembic/       # migration environment + versions/
```

## Database schema

See `app/models/` for the source of truth. Tables: `users`, `broker_connections`,
`executions`, `trades`, `trade_executions` (join table), `strategies`,
`trade_notes`, `screenshots`, `daily_performance`.

## Adding a migration after changing a model

```bash
alembic revision --autogenerate -m "describe the change"
alembic upgrade head
```

Always review the autogenerated migration file before running it — autogenerate
is a good first draft, not a guarantee.
